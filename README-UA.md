# Willa Check-in 0.1.0

Пробний локальний Electron-застосунок для підготовки документів гостей. Інтерфейс польською. Робоча ціль — Windows 10/11 x64.

## Запуск готової програми

Розпакуйте загальний архів і запустіть `Willa-Checkin-0.1.0-Windows.exe`. Node.js, Word, браузер, сервер, API-ключі й інтернет для роботи готової програми не потрібні. Перше розпакування portable-програми може зайняти трохи часу.

Windows-файл не має цифрового підпису видавця. Якщо запуск обмежений політикою робочого ПК, передайте програму адміністратору для перевірки. Програму не потрібно запускати від адміністратора.

## Робота рецепції

1. Перетягніть PDF-підтвердження у верхню область або натисніть **Wybierz pliki**.
2. Виберіть запис зліва. Перевірте і за потреби допишіть дані посередині. Зміни одразу потрапляють у перегляд справа.
3. На нижньому рядку виберіть склад комплекту: картка гостя, інформація для гостя, повна інформація про персональні дані.
4. Позначте потрібні бронювання зліва.
5. **Zapisz PDF** збере всі вибрані документи в один PDF. **Drukuj wybrane** відкриє системний діалог друку.

Порожні поля дозволені й залишаються порожніми на папері. Вручну можна створити запис через **Dodaj ręcznie**. Для збереження лише одного бронювання зніміть вибір з інших.

## Мова

`+48` → польська; `+420` → чеська; `+49` → німецька; інший розпізнаний міжнародний код → англійська. Префікс `00` також підтримується. Без телефону, без міжнародного коду або з нерозпізнаним кодом — польська. Мову можна вибрати вручну; тоді наступна зміна телефону її не змінить. Країна проживання за номером не визначається.

## Шаблони

Картка гостя: PL, CZE, DEU, ENG. Підготовлено з наданих Word-документів; шрифт трохи зменшено, щоб кожна картка займала одну сторінку A4. Логотип, таблиця, текст згод і місця для підписів збережено. Згоди й підписи не заповнюються автоматично.

Інформація для гостя: три варіанти PL і CZE; стандартний DEU. Повна інформація про персональні дані: CZE, DEU, ENG. Ці інформаційні листки переверстано для одного гостя без дублювання копій. Відсутніх перекладів не додано. Програма повідомить про відсутні шаблони перед збереженням чи друком.

У наданому чеському варіанті «без ресторану» залишився текст про ресторан. Він не виправлений довільно: у програмі є попередження та додаткова перевірка перед експортом. Поточні ціни послуг, правила та юридичні формулювання успадковано з ваших документів; їх затвердження не входило до цієї версії.

Поверх обирається вручну: програма не виводить його з номера кімнати. Формулювання про включене харчування не виводиться автоматично з вартості бронювання.

## Межі пробної версії

- Підтримані текстові PDF двох наданих форматів: системні підтвердження та індивідуальний лист. Інший макет може потребувати нового парсера. HTML ще не підтримується.
- Один PDF — один запис бронювання. Файл із кількома виявленими номерами бронювань не змішується в одного гостя: створюється порожній запис із попередженням. Кілька кімнат в одному підтвердженні потрібно розділити вручну на записи.
- Скановані або захищені паролем PDF потребують ручного вводу чи попередньої підготовки. OCR немає.
- Тип кімнати не використовується як кількість гостей. Передоплата не підставляється замість вартості проживання. Телефон та email готелю не використовуються як контакт гостя.
- Ліміт — 100 бронювань за сесію, 25 МБ та 30 сторінок на PDF. Ідентичні файли не імпортуються двічі.
- Результати завантажуються як PDF; редагований DOCX не генерується.
- Список гостей зберігається лише в пам’яті поточного запуску. Після закриття він зникає. Експортовані PDF залишаються у вибраному вами місці.
- Програма працює локально, без аналітики й зовнішніх API. Тимчасові сторінки для експорту видаляються після завершення операції; після аварійного завершення можуть залишитися в системній тимчасовій папці `willa-checkin-*`.
- Відправлення в системну чергу друку не підтверджує фізичний вихід паперу. На вашій моделі принтера потрібна проба A4 у масштабі 100%.

## Запуск із вихідного коду

Потрібен Node.js 22.16+ або новіший LTS та інтернет для першого встановлення залежностей.

```bash
npm ci
npm start
```

Збирання portable Windows-файла:

```bash
npm run dist:win
```

Результат з’явиться в `dist/`. Для швидшої локальної збірки можна передати `ELECTRON_BUILDER_COMPRESSION_LEVEL=3` як змінну середовища. Завантаження Electron та інструментів збірки потребує інтернету.

## Структура коду

| Файл | Призначення |
| --- | --- |
| `app/main.cjs` | Вікно Electron, імпорт, діалоги, принтери, експорт PDF |
| `app/preload.cjs` | Обмежений API між інтерфейсом і системою |
| `app/renderer.mjs` | Список бронювань, редактор, автоматичний вибір мови |
| `src/pdf.mjs` | Читання PDF через PDF.js і відновлення порядку тексту |
| `src/parser.mjs` | Витягування полів, мови та перевірки |
| `src/documents.mjs` | Документи A4 для однакового перегляду, PDF і друку |
| `templates/catalog.json` | Тексти й координати полів |
| `templates/card-*.svg` | Векторні основи чотирьох карток |
| `templates/source/` | Оригінальні порожні Word-шаблони |

Не вставляйте персональні дані в код. Тестові підтвердження гостей до цього архіву не включено.

Для регенерації шаблонів розробнику потрібні Python, `lxml`, `PyMuPDF` та LibreOffice із `soffice` у PATH. Команди: `python scripts/render-cards.py`, потім `python scripts/prepare-templates.py`. Після зміни макетів перевірте координати полів і всі сторінки.

## Перевірка цієї версії

Пройдено модульні перевірки, імпорт усіх трьох наданих PDF із порівнянням полів, запуск справжнього Electron, редагування, перемикання мов, пропуск дублікатів та пакетний експорт. Перевірено відображення чотирьох карток і доступних інформаційних документів у багатомовній пачці.

```bash
npm test
```

Окрема перевірка на приватних наданих PDF доступна через `npm run test:fixtures`: покладіть три початкові PDF до сусідньої папки `upload` або задайте її шлях змінною `CHECKIN_FIXTURES`.

Сам Windows portable-файл зібрано для x64, але запуск під Windows і фізичний друк у цьому середовищі не виконувалися.
